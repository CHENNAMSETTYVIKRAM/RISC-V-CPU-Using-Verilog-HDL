### 1.2 Distinction Between Python Simulation & Native RTL Simulation
- The test results recorded in `TEST_REPORT.md` and `SIMULATION_RESULTS.md` were generated by executing `scripts/verify.py`.
- **Nature of the Engine**: `scripts/verify.py` is a **Python-based cycle-accurate architectural simulator** that implements the exact stage-by-stage registers, forwarding multiplexer equations, load-use hazard interlocks, and branch redirection of the RISC-V architecture.
- **Clarification**: This Python simulation serves as a bit-accurate and cycle-accurate reference model; it is **NOT** a native compiled Verilog RTL simulation by an event-driven logic simulator like ModelSim or Icarus Verilog.
- **Native Testbenches**: For users with ModelSim or Icarus Verilog installed, complete native Verilog testbenches are provided in `day1/tb/`, `day2/tb/`, `day3/tb/`, and `day4/tb/` (e.g. `cpu_tb.v`, `cpu_pipe_tb.v`, `alu_tb.v`, `fifo_tb.v`).

### 1.3 Distinction Between Static Linting & Logic Synthesis
- The checks performed by `scripts/lint_synth_check.py` constitute **rule-based static RTL linting** (verifying complete `if-else` branches, explicit `case` default assignments, absence of unintended latch inference, and proper separation of blocking `=` and non-blocking `<=` assignments).
- **Clarification**: Static linting validates that the Verilog code conforms to synthesizable coding standards; it is **NOT** physical logic synthesis and does not place, route, or generate gate-level netlists.
- No commercial FPGA synthesis tool (Xilinx Vivado, Intel Quartus) was executed in this environment. Consequently, no physical FPGA Worst Negative Slack (WNS) or place-and-route timing closure numbers are claimed.

### 1.4 Waveform Generation Notice
- VCD waveform files in `day1/waves/` through `day4/waves/` were produced by the simulation tracer `scripts/generate_waveforms.py` using cycle-accurate state traces from the architectural simulation.
- Native testbenches also include `$dumpfile` and `$dumpvars` directives so that when executed under Icarus Verilog (`vvp`) or ModelSim, identical authentic VCD traces are dumped directly by the EDA tool.

## 3. How to Execute Native RTL Simulation with Icarus Verilog

When Icarus Verilog is installed, each activity can be compiled and simulated natively:

```bash
# Day 1: Parameterized ALU Testbench
iverilog -g2012 -o sim_alu day1/src/alu.v day1/tb/alu_tb.v
vvp sim_alu

# Day 2: Synchronous FIFO Testbench
iverilog -g2012 -o sim_fifo day2/src/fifo.v day2/tb/fifo_tb.v
vvp sim_fifo

# Day 3: Single-Cycle CPU Testbench (All 6 Programs)
iverilog -g2012 -o sim_cpu day3/src/*.v day3/tb/cpu_tb.v
vvp sim_cpu

# Day 4: 5-Stage Pipelined CPU Testbench (Hazards & Benchmarks)
iverilog -g2012 -o sim_pipe day4/src/*.v day4/tb/cpu_pipe_tb.v
vvp sim_pipe
```
